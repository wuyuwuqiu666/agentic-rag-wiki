# Runbook：密钥轮换（E8 安全合规工程 / T1 凭证红线）

**适用范围**：云 LLM/embedding API key（`APP_CLOUD_LLM_API_KEY` / `APP_CLOUD_EMBEDDING_API_KEY`）、数据库连接串（`APP_PG_DSN`，含口令）、向量库凭证（`APP_MILVUS_URI`/token）。
**红线口径**：凭证只从环境变量/系统密钥库读入（keychain/secret store），**严禁**写入代码、`.env`（`.env` 已被 `.gitignore` 且仅本机）、配置文件、日志或审计 `detail`（`AuditEvent` 只带 trace/计数，不带明文 key）。提交前 `harness/secret_scan.py` 命中任一 secret 即阻断（T1/NFR-3）。

## 轮换节奏
- **计划轮换**：月度（§15 E8「每 PR + 月度」时机）。
- **事件轮换**（立即，不等月度）：疑似泄露/离职人员曾接触/供应商告警/密钥扫描误报被证实/`B4` 或 `provider_fail_loud` 指向凭证外泄。

## 标准动作（在线双钥并行，零停机）
1. **备**：在供应商控制台新建第二把 key（旧 key 暂不吊销）。新 key 只落系统密钥库/受控 secret 注入，**不进 git、不进本机 `.env` 明文提交**。
2. **切**：更新运行环境注入源（部署侧 secret→env），滚动重启进程或触发配置重载。`Settings` 于装配根读取（E2 fail-fast：选了云档缺凭证→启动即失败，不静默降级到 dev 档）。
3. **验**：跑一次最小只读冒烟（`Admin.replay_audit` 之外，另发一次健康问答或单条 embed），确认新 key 生效、无 `provider_fail_loud` 激增。
4. **撤**：观察一个短窗口（建议 ≥1 小时且覆盖一次读侧调用）无异常后，**吊销旧 key**。
5. **记**：记录轮换事件（轮换时间、操作者、密钥指纹/后四位，**绝不记明文**）；若平台侧有配置变更留痕要求，按 `param_change` 语义走人工登记（单机执行档不自动改参数，见 AGENTS §8 放行项⑩）。

## 回滚点
- 第 3 步验证失败（新 key 不通/权限不足）：**立即切回旧 key 注入源**并重启，旧 key 此时尚未吊销仍可服务；排查后重来。
- 已吊销旧 key 后才发现新问题：以第 2 步保留的新 key 为准修复配置，不回退到已吊销凭证。

## 双人/审批
- 生产密钥吊销（第 4 步）与事件轮换建议**双人确认**（一人操作、一人复核），与 B1 双人复位同口径；真·跨人审批工作流属 E9/企业档放行（本 runbook 先规定动作与留痕，不落自动审批系统）。

## 未决（实机放行项）
- 密钥库托管（Vault/KMS/云 Secrets Manager）、自动轮换到期提醒作业、SBOM/CVE 与许可证门禁自动化 = 企业/运行时档（见 AGENTS §8 E8 放行项），本机档以人工流程 + `secret_scan` 门禁兜底，不伪造自动轮换调度。
