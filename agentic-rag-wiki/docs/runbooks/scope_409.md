# Runbook：可见域后端划分与 409 处置（FR-MEM-2 / M4-ca）

范围口径=**读侧"谁能看哪些知识域"的唯一解析点，与 409 的两种成因**。页可见性动作见 `wiki_review.md`，块级 ACL 变更见 `ingest_retire.md`。

## 唯一口径（一条链，四条入口共用）
`_reader_domains(role, acl, portraits)`（`gateway/http.py:238`）是门面**唯一**的可见域解析点，`/api/ask`·`/api/source`·`/api/wiki/pages`·`/api/wiki/review` 全经此处——防止"某条入口少判一次"造成口径漂移。它只决定"**以哪些域问**"，不实现"**怎么过滤**"：过滤一律在 `App` 内以 `can_read_field` 作 **pre-filter**（候选出网前就挡掉，不是拿到答案再抹）。

两条分支：
- **`role` 在位**＝后端按 C 区**角色聚合画像**划分：可见域＝该角色 `scope=="role"` 全部画像 `acl_tags` 的并集（排序去重）。跨域角色的并集由后端算出，前端不拼勾选。
- **`role` 缺位（None）**＝退回调用侧声明的 `acl`（承 dev 兜底，语义同 CLI `--acl`）。**这不是降级放行**：两路拿到的域在 `App` 内过同一道 pre-filter。

## 409 的两种成因（都是预期行为，不是故障）
`visible_domains`（`memory/service/domain_scope.py:21`）只抛两类 `ValueError`，门面统一翻 **409 且不给任何域**：

| 现象 | 成因 | 处置 |
|---|---|---|
| `角色 'x' 无画像聚合（键 k），后端不划分任何知识域` | 该角色尚无 `PortraitAgg`（冷启动 / 新角色 / 角色名与画像键不符） | 见下方三条出路 |
| `角色标识不合法（空或含首尾空白）：'…'` | 角色名带首尾空格（`" admin "` 一类） | 修调用方；这是**唯一能到判定层的非法输入** |

**空串与超长到不了判定层**：`AskRequest.role` 与 `?role=` 都带 `min_length=1`/`max_length=64`，空串或 65 字符在 **schema 校验层即 422**（T2 外部输入先过门），不会变成 409。读到 422 就按客户端错误修请求，别去查画像。

**冷启动不放行是安全设计**：画像未建立时若"暂时给全域"，等于把 FR-MEM-2 的读门变成开关。`GET /api/scope?role=` 同口径，前端因此可以只显示不可改。

## 处置路径（按优先级）
1. **等画像自然形成**：`PortraitAgg` 由 C 区学习回路按聚合粒度写入（真实按主体归因=鉴权放行档，见下方诚实账）。生产新角色属正常等待态，用户侧应看到"该角色暂无可答范围"而不是报错页。
2. **本次调用退回 `acl` 声明**：不带 `role`、带 `acl=fin,hr`，用于运维核验与非画像场景（`/api/ask` 两路都收）。
3. **dev/演示档**：`_create_app` 恒执行 `seed_demo`，它 seed 四条角色画像——`finance-analyst→fin`、`hr-partner→hr`、`release-oncall→eng`、`kb-auditor→eng+fin`（**合成聚合单元，非真实业务统计样本**，不得据其得出任何命中率/覆盖率结论）。用这四个角色名即无 409；用其它名必 409，因为键不匹配而非"权限被拒"。

## 禁止事项
- **不要**为了消除 409 而把"无画像"改成"默认全域"或"默认某个域"。
- **不要**在前端保存或下发域列表当作权限依据——前端只显后端算出的结果。
- **不要**关掉 `seed_demo` 来"净化"演示环境：关掉后 `/api/ask` 因画像缺失一律 409，看起来像问答坏了，实际是权限门在正常工作。要核验就保留 seed 并把断言钉在自己那批 doc/chunk id 上。

## 诚实边界（在册放行档）
- 聚合粒度、会话 TTL、ACL 读门三层保护的**策略层已执法**；**按已鉴权主体（SSO/LDAP 身份）归因画像＝鉴权放行档**，执行档只按 `role` 字符串取画像，`role` 本身未经鉴权——它不是身份凭证，别把它当授权依据跨信任边界使用。
- 画像的持久化与跨进程读回随 PG 落地（放行项②）。
