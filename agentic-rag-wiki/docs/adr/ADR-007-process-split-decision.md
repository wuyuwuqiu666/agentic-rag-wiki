# ADR-007：分区进程级拆分决策点——单机执行档默认不拆

- 状态：采纳
- 日期：2026-09-28
- 关联：R10「分区制超前于团队规模」；§4「进程级拆分推迟到 M4 压测后按需」；§6.1 跨区契约；G5 组件可替换。

## 背景
系统按"平台平面 + 三分区（A 摄取 / B wiki / C 记忆）"仓库级目录隔离，跨区只经契约 + 事件（`CanonicalEvent` fan-out、`IngestionPort` 回写）。§4 已裁决进程级拆分推迟到 M4 压测后按需决策。M4 到达该决策点。

## 决策：执行档=默认不拆（单进程）
- 单机执行档（≤5 并发、5 万文档，ADR-005）下，单进程足以承载；拆分**只增运维负担、无吞吐收益**，且会引入本机本不需要的 RPC/序列化/独立 DB 成本（R10 纯负债）。
- 爆炸半径的隔离**已由结构保证**：分区目录=import 执法边界（`check_imports` 跨区三禁）+ 契约 + 事件流，无需靠进程边界再补。

## 拆分触发条件（企业档，按需逐个拆）
当且仅当出现下列任一，才把对应分区拆独立进程：
1. 某分区 CPU/显存饱和需**独立扩缩**（如 A 区 embed 常驻挤占 B 区编译）；
2. **故障隔离**需要（写侧摄取崩溃不应带走读侧问答）；
3. 供给档位差异要求分池调度。
拆分时**跨区调用走 §6.1 既有契约**（进程边界替换端口实现，业务链与事件语义不变）。

## 可逆性
- 契约与事件流不变 → 拆/合是可逆装配决策，成本低（G5）；单机↔多机切换不动业务代码。
- 当前**不预写**跨区 RPC / 独立 DB schema（R10 对冲，避免单人单机的过度工程）。
